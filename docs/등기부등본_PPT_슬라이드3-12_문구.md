## 슬라이드 3. 1단계 – 문서를 텍스트로 변환

**제목:** OCR 기반 문서 인식

**본문 (불릿):**
- PDF / 이미지 형태의 등기부등본 입력
- **EasyOCR**을 활용한 텍스트 인식 (한글·영어)
- 한글·숫자 인식 오류 발생 가능
- 등기부 특성에 맞는 **규칙 기반 오타 보정** 적용
- ※ 이 단계에서 **딥러닝 기반 OCR 모델** 사용 (AI 적용 구간)

## 슬라이드 4. OCR 성능 개선 과정

**제목:** OCR 인식 정확도 개선

**초기 OCR 결과의 문제점**
- 공백이 끼어든 용어 (예: "소 재 지", "면 적")
- 등기부 용어 오인식 (표게부, 표계부, 표재부, 표개부 → 표제부)
- 단위 표기 불일치 (m2, m² → ㎡)

**개선 방법**
- 등기부 전용 **키워드 사전** 적용 (표제부 등 오타 → 정답 용어 매핑)
- **정규식**으로 공백 분리된 단어 합치기 (소재지, 면적)
- 단위 통일 규칙 (㎡)
- **모델 재학습 없이** 후처리만으로 성능 개선

## 슬라이드 5. OCR 결과 전/후 비교

**제목:** OCR 결과 비교 시각화

**표 구성 예시 (좌우 또는 상하 비교)**

| 구분 | 개선 전 OCR 텍스트 | 개선 후 보정된 텍스트 |
|------|---------------------|------------------------|
| 용어 | 표게부 / 표계부 | 표제부 |
| 주소 관련 | 소 재 지 | 소재지 |
| 면적 관련 | 면 적 85 m2 | 면적 85 ㎡ |

- 위와 같은 **표** 또는 **하이라이트**로 주요 오류가 줄어든 부분 강조
- (실제 서비스에서 캡처한 예시가 있으면 그걸 쓰면 더 좋음)

## 슬라이드 6. 2단계 – 등기부 내용 구조화

**제목:** 텍스트를 구조화된 데이터로 변환

**본문 (불릿):**
- 인식·보정된 텍스트를 **표제부 / 갑구 / 을구**로 구분
- **표제부**: 주소, 건물명, 동·호, 면적
- **갑구**: 소유자, 소유권 이전 이력
- **을구**: 근저당·전세권 등 **권리** 목록
- **규칙과 정규식**으로 키워드·패턴 매칭 후 추출
- ※ 이 단계는 **규칙 기반 처리** (LLM 사용 안 함)

## 슬라이드 7. 3단계 – 위험 요소 분석

**제목:** 위험 신호 탐지 로직

**본문 (불릿):**
- 구조화된 데이터를 기반으로 **사전 정의 조건(if / rule)**으로 위험 판단
- **공동 소유** 여부 (공동 표시, 지분, 소유자 수)
- **권리** 존재 여부 및 건수 (근저당·전세권 등)
- **소유권 이전 이력** 유무 및 시점
- **주소·동호** 추출 여부 (목적물 특정 가능 여부)
- 위험 신호 문장 생성 + **체크리스트 항목** 생성 (소유자 확인, 권리 확인 등)

---

## 슬라이드 8. 위험 분석 로직 개선

**제목:** 위험 판단 정확도 개선

**초기 설계 시 고려한 점**
- 표제부·갑구·을구 **구역 분리** 규칙으로 항목별 정확한 추출
- **복합 조건** 적용 (예: 공동 소유 + 소유자 2명 이상, 권리 건수 > 0)
- 소유자 이름 추출 시 한글 이름 패턴·중복 제거
- 주소/동/호 미추출 시 별도 위험 플래그로 안내

**결과**
- 구조화 정확도에 따라 위험 탐지 신뢰도 향상
- 일관된 형식의 체크리스트로 사용자 확인 항목 명확화

## 슬라이드 9. 4단계 – 쉬운 설명 생성

**제목:** 생성형 AI를 활용한 사용자 설명

**본문 (불릿):**
- 분석된 **위험 신호 목록**을 입력
- **GPT(OpenAI API)**로 다음 형식의 설명 생성:
  - 법률 용어 배제
  - 중학생도 이해할 수 있는 쉬운 문장
  - 한 줄 요약 → 뜻 설명 → 주의할 점 → 추가로 확인할 것
- 시스템 프롬프트: "부동산 등기부 정보를 쉽게 설명하는 안내 AI. 법적 판단은 하지 않음."
- ※ **생성형 AI 사용 구간**

## 슬라이드 10. 성능 개선 요약

**제목:** 개선 전·후 비교 요약

**불릿:**
- **OCR**: 어휘 보정으로 등기부 용어·단위 인식 정확도 향상
- **구조화**: 표제부/갑구/을구 규칙으로 추출 안정성 확보
- **위험 분석**: 조건 로직 정교화로 위험 요소 누락 감소
- **설명**: GPT로 사용자 이해도 개선
- **전체**: 설명 가능한 규칙 + AI 조합으로 서비스 신뢰도 향상

(정량 지표가 있으면 여기에 수치 추가)

## 슬라이드 11. AI 사용 범위 정리

**제목:** AI는 어디에 사용되었는가?

**표 예시:**

| 단계 | 사용 기술 | AI 여부 |
|------|-----------|--------|
| 문서 → 텍스트 | EasyOCR | ✅ 딥러닝 OCR |
| OCR 후처리 | 규칙·어휘 사전 | ❌ 규칙 기반 |
| 텍스트 구조화 | 정규식·규칙 | ❌ 규칙 기반 |
| 위험 신호·체크리스트 | 조건 로직 | ❌ 규칙 기반 |
| 쉬운 설명 문장 | GPT (OpenAI) | ✅ 생성형 AI |

- **AI를 필요한 구간에만** 적용한 설계 (비용·설명 가능성 고려)
